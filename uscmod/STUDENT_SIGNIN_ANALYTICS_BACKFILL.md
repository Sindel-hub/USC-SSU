# Student Sign-in Analytics — Pre-feature Account Backfill

The officer analytics now includes student accounts that existed before `student_signin_stats` was introduced.

## Behavior

- When the System Administrator opens any Admin Dashboard page that subscribes to the user directory, missing student analytics records are created automatically.
- Every existing student account with a College/Campus is added as a baseline analytics record.
- If the student profile already contains a trustworthy `lastLoginAtMs` / `lastLoginAt`, the backfill restores one historical sign-in for that account.
- If no older login timestamp exists, the account is still included in **Known accounts**, but its sign-in count remains `0`. The system does not invent historical logins.
- On that student's next successful portal login, the zero-count baseline is upgraded to the first tracked sign-in and `firstSignInAt` / `lastSignInAt` are set.
- The Officer Dashboard now shows both **Known accounts** and **Unique students signed in** by department.

## Optional deeper historical recovery

`scripts/backfill-student-signin-analytics.mjs` can be run with Firebase Admin credentials. It checks Firebase Authentication metadata, but deliberately ignores the account-creation sign-in generated by browser provisioning. Only an Auth last-sign-in clearly later than account creation is treated as historical student activity.

Run with:

`npm run backfill:signin-analytics`

The existing Firebase Admin scripts in this project use Application Default Credentials in the same way.

## Important

Deploy the included `firestore.rules` first. The updated rules allow the trusted System Administrator to create constrained legacy analytics baseline records while students remain limited to incrementing only their own sign-in record.
